# Guía de entrega — SCRUM Semana 3

## Objetivo

Usar el material versionado en esta carpeta para preparar la evidencia solicitada por UCAMP en una herramienta colaborativa, sin cambiar el contenido del User Story Mapping.

## Material listo

- [User_Story_Mapping_MVP.md](User_Story_Mapping_MVP.md): explicación completa y trazabilidad de la rúbrica.
- [Tablero_User_Story_Mapping.svg](Tablero_User_Story_Mapping.svg): tablero visual en formato panorámico, listo para abrir en navegador o colocar como referencia en Miro/Mural.

## Montaje recomendado en Miro o Mural

1. Crea un tablero nuevo y pon como título **Mochi Monchi — User Story Mapping & MVP**.
2. Usa cinco columnas, de izquierda a derecha:
   - Revisar turno
   - Registrar pedido
   - Confirmar venta
   - Actualizar operación
   - Cerrar y aprender
3. Crea tres franjas horizontales:
   - **Release 1 — MVP**
   - **Release 2 — Siguiente prioridad**
   - **Backlog futuro**
4. Usa el SVG como referencia visual o súbelo al tablero para conservar el orden.
5. Si tu instructor espera tarjetas editables, reproduce cada historia del MVP como nota adhesiva usando los textos US-01 a US-10 del documento principal.
6. Mantén un color claramente distinto para cada release. Lo importante es que el MVP pueda identificarse a simple vista.
7. En la parte inferior agrega una nota llamada **Feedback del MVP** con:
   - tiempo de registro;
   - correcciones;
   - faltantes detectados;
   - valoración de 1 a 5; y
   - comentario opcional del operador.

## Capturas recomendadas

### Captura 1 — Vista completa

Debe mostrar en una sola imagen:

- título del proyecto;
- las cinco etapas del recorrido;
- Release 1/MVP;
- Release 2;
- backlog futuro; y
- leyenda de colores.

Esta captura demuestra que el User Story Mapping visualiza claramente la experiencia del usuario y que el MVP está separado del resto del backlog.

### Captura 2 — MVP y feedback

Haz una segunda captura más cercana donde se lean las historias del MVP y la sección de feedback.

Esta captura demuestra que las funciones seleccionadas permiten aprender de una primera prueba real.

## Texto breve para la plantilla de UCAMP

Puedes acompañar las capturas con este texto:

> El MVP de Mochi Monchi conecta el registro de pedidos con las recetas y el inventario. La primera versión permite completar el flujo principal del operador sin duplicar información y deja fuera funciones que no son indispensables para validar la hipótesis. Para obtener retroalimentación se observarán el tiempo de registro, las correcciones y los faltantes detectados; además, al cierre del turno el operador podrá registrar una valoración de 1 a 5 y un comentario opcional. Con esta evidencia se priorizará la siguiente iteración del backlog.

## Checklist antes de entregar

- [ ] El recorrido puede leerse de izquierda a derecha.
- [ ] El MVP se distingue visualmente de Release 2 y del backlog futuro.
- [ ] Las historias del MVP son suficientes para completar un flujo de principio a fin.
- [ ] El tablero muestra cómo se recolectará feedback.
- [ ] Las capturas tienen texto legible y no cortan columnas.
- [ ] Las capturas están insertadas en la plantilla de la Semana 2/3 indicada por UCAMP.
- [ ] Revisé ortografía, nombres y consistencia con el Product Vision Board de la Semana 2.
