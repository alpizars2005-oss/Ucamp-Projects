# Definición del Caso de Estudio — SCRUM Semana 1

## Proyecto seleccionado

**Mochi Monchi - Sistema digital de pedidos e inventario**

Producto de software para centralizar el catálogo, pedidos, recetas, inventario de ingredientes y desechables, costos y reportes operativos del negocio. La solución se desarrollará de forma modular para incorporar nuevas funciones conforme se validen necesidades reales.

## Justificación del uso de Scrum

El proyecto se beneficia de Scrum porque combina desarrollo de software con necesidades reales de operación que pueden cambiar conforme el negocio crece. Al inicio conocemos funciones básicas —catálogo, pedidos, recetas e inventario—, pero no todos los requisitos pueden definirse con precisión desde el principio. La forma de capturar pedidos, los reportes útiles, las reglas de descuento o la manera de descontar ingredientes pueden ajustarse después de probar el sistema en situaciones reales.

Scrum permite trabajar en incrementos pequeños y funcionales, priorizando primero lo que aporta mayor valor al negocio. Cada sprint puede entregar una mejora utilizable, recibir retroalimentación y ajustar el backlog antes de continuar. Esto reduce el riesgo de invertir demasiado tiempo en funciones que después deban cambiar y facilita responder a nuevos productos, promociones o necesidades de operación.

Frente a un enfoque tradicional, Scrum resulta más adecuado por la incertidumbre de los requisitos, la necesidad de validación frecuente y la posibilidad de evolucionar el producto de forma continua.

## Matriz inicial de roles — Scrum Team

Al tratarse de un proyecto académico individual, una misma persona asume temporalmente las tres responsabilidades. Para aplicar Scrum correctamente, se mantiene clara la separación entre las decisiones de producto, la facilitación del marco y el trabajo de desarrollo.

| Rol | Quién lo ocupa | Responsabilidades en el proyecto |
|---|---|---|
| **Product Owner** | Ángel Alfredo Alpizar Sánchez | Define la visión del producto, representa las necesidades del negocio, ordena el Product Backlog por valor, aclara requisitos y valida si cada incremento satisface el objetivo del sprint. |
| **Scrum Master** | Ángel Alfredo Alpizar Sánchez | Facilita la aplicación de Scrum, promueve transparencia e inspección, ayuda a mantener eventos y objetivos claros, identifica impedimentos y protege el enfoque del sprint. |
| **Development Team** | Ángel Alfredo Alpizar Sánchez | Analiza, diseña, programa, prueba y documenta los incrementos. Estima el trabajo, selecciona tareas del sprint y asegura que cada entrega cumpla los criterios de calidad acordados. |

## Por qué el caso encaja con un marco ágil

- **Incertidumbre:** los requisitos se afinan al observar el uso real del sistema.
- **Retroalimentación:** cada incremento puede validarse antes de ampliar el alcance.
- **Valor temprano:** las funciones prioritarias pueden ponerse en uso desde los primeros sprints.

## Cobertura de la rúbrica

- **Proyecto claro:** se define un producto de software concreto y utilizable para la operación del negocio.
- **Justificación Scrum:** se explica explícitamente la incertidumbre de requisitos, la complejidad evolutiva y el valor de iterar con retroalimentación.
- **Roles correctos:** se distinguen las responsabilidades de Product Owner, Scrum Master y Development Team dentro del contexto individual.

## Resultado esperado

Al finalizar la semana queda definido el caso de estudio que servirá como base para aplicar Scrum durante el resto del módulo, permitiendo construir el producto de manera incremental y mantener trazabilidad entre necesidades, backlog y entregas.
